## ฟีเจอร์ใหม่ใน v1.2.0: cache ที่ดู "เนื้อไฟล์" จริง — ย้าย/เปลี่ยนชื่อ/ย้ายเครื่องก็ไม่คำนวณใหม่

v1.1.2 ยังมีปัญหาที่เจอจริง: **"ย้ายไฟล์แคชแล้วมันยังเริ่มคำนวณรูปใหม่หมดทั้งที่ทำแคชไว้แล้ว"**
สาเหตุคือ cache ยังผูกกับ *ชื่อไฟล์ + ขนาด + mtime + crc32* ซึ่งพังได้หลายทาง:

- ย้าย/เปลี่ยนชื่อ **โฟลเดอร์ย่อย** ภายในฐานข้อมูล → ชื่อไฟล์เดิมแต่ path เปลี่ยน = ไม่เจอ cache
- แก้ mtime (copy, zip/unzip, sync, restore backup) → ต้องไล่ hash ใหม่ทั้งคลังทุกครั้ง
  และ mtime ที่แก้แล้วไม่ถูกบันทึกกลับ (บั๊กเดิม) → hash ซ้ำทุกครั้งที่เปิด
- เปลี่ยนชื่อไฟล์รูป (เช่นเติม suffix) → วิเคราะห์ใหม่ทั้งที่เนื้อรูปเหมือนเดิม
- crc32 มีโอกาสชนกัน (birthday) ~3% เมื่อมี ~16,000 ไฟล์

v1.2.0 เปลี่ยนหัวใจของ cache เป็น **SQLite ที่ key ด้วย BLAKE2b-128 ของเนื้อไฟล์**:

- **ย้ายโฟลเดอร์ / เปลี่ยนชื่อไฟล์ / จัดโฟลเดอร์ย่อยใหม่ / คัดลอกไปเครื่องอื่น**
  → ใช้ embedding เดิมทั้งหมด ไม่เรียกโมเดลเลย (ตรวจแค่เนื้อไฟล์)
- **ย้ายโฟลเดอร์ `deepface_cache` ไปที่ใหม่** → เปิดมาใช้ cache ได้ทันที
  (cache อยู่ในโฟลเดอร์ฐานข้อมูลเสมอ ไม่ผูกกับ path เต็ม)
- **บันทึกทีละชุดระหว่างทำงาน** (SQLite) แทนการเขียนทับไฟล์ `.npz` ทั้งก้อน
  → รันแรกเร็วขึ้น, กด "หยุด" แล้วหยุดทันที, ข้อมูลที่ทำเสร็จแล้วไม่หาย
- **แคชใช้ร่วมกันทั้งเครื่อง** — รูปเนื้อเดียวกันที่เคยวิเคราะห์ในโฟลเดอร์ฐานข้อมูลอื่น
  จะถูกนำมาใช้ซ้ำทันที (เก็บที่ `%LOCALAPPDATA%\Deeface\cache`)
  ปิดได้ด้วย environment variable `DEEFACE_SHARED_CACHE=0`
- **อัปเกรด cache เก่าอัตโนมัติ** (v1.0–1.1 `.npz`) — อ่าน + hash หนึ่งรอบ
  ไม่เรียกโมเดล (คลัง 16,000 รูป ~1 นาที) หลังจากนั้นใช้รูปแบบใหม่ตลอด
- **รูปที่วิเคราะห์ไม่สำเร็จจะไม่ถูกจำว่า "ไม่พบใบหน้า"** — ข้ามไปแล้วลองใหม่รอบหน้า
  ถ้าล้มติดกัน 5 ไฟล์โดยยังไม่มีไฟล์ไหนสำเร็จเลย จะหยุดพร้อมแจ้งว่าเป็นปัญหา
  สภาพแวดล้อม/โมเดล (ไม่ทำให้ cache เสีย)
- **หน้าโปรแกรม:** แสดงสถานะแคช (จำนวนไฟล์/ใบหน้า/ขนาด) และปุ่ม **♻ รีเซ็ตแคช**
  สำหรับกรณีที่ต้องการบังคับวิเคราะห์ใหม่จริง ๆ

## ฟีเจอร์ใหม่ใน v1.1.0: cache ที่ไม่ขึ้นกับตำแหน่งโฟลเดอร์

v1.0.0 เก็บ cache ตาม **path เต็ม** ของไฟล์ (เช่น `D:\TEMP\xxx.jpg`) —
ดังนั้นถ้าย้ายโฟลเดอร์ฐานข้อมูลไปไว้ในที่ใหม่ (หรือย้ายเครื่อง) cache จะหมดอายุ
ต้องสแกนใหม่หมดทั้งหมื่นกว่ารูป (~1 ชั่วโมง)

v1.1.0 เก็บ cache ตาม **ชื่อไฟล์ + ขนาดไฟล์ + เวลาแก้ไข** (ไม่ขึ้นกับตำแหน่ง) —

- **ย้ายโฟลเดอร์/ไดรฟ์** (ชื่อไฟล์ไม่เปลี่ยน) → cache ยังใช้ได้เลย 100%
  รันถัดไปโหลดในไม่กี่วินาที ไม่ต้องสแกนใหม่
- **เพิ่มรูปใหม่** → วิเคราะห์เฉพาะรูปใหม่เท่านั้น (เหมือนเดิม)
- **เปลี่ยน/แทนที่รูป** (ชื่อเดิม แต่ไฟล์คนละตัว) → โปรแกรมตรวจพบและ
  วิเคราะห์รูปนั้นใหม่โดยอัตโนมัติ
- cache เก่า (v1.0.0) ใช้ต่อได้ทันที — โปรแกรมแปลงเป็นรูปแบบใหม่ให้
  อัตโนมัติตอนรันแรก

### v1.1.1 — cache ทนการคัดลอกข้ามเครื่อง (crc32)

v1.1.0 มีพฤติกรรมว่าถ้าไฟล์ถูก **คัดลอกไปเครื่องอื่นแล้ว mtime (timestamp)
เปลี่ยน** (เช่น copy ด้วย Explorer, zip/unzip, sync) แอปจะคิดว่าไฟล์ทุกไฟล์
"เปลี่ยน" แล้ววิเคราะห์ใหม่ทั้งคลัง (~54 นาที)

v1.1.1 แก้โดยเพิ่ม **crc32 (checksum ของเนื้อไฟล์)** เป็นตัวตัดสินจริง:
- mtime ตรงกัน → ใช้ cache ทันที (fast path, ไม่อ่านไฟล์)
- mtime เปลี่ยนแต่ขนาดเท่าเดิม → ตรวจ crc32 ของเนื้อไฟล์ (อ่านไฟล์ครั้งเดียว
  ~หลักนาทีสำหรับทั้งคลัง) → เนื้อไฟล์เท่าเดิม = ใช้ cache เท่าเดิม
- เนื้อไฟล์เปลี่ยน (แทนรูป) → วิเคราะห์ใหม่เฉพาะไฟล์นั้น

หมายเหตุ (v1.2.0): ข้อความด้านบนบรรยายพฤติกรรมของ v1.1.x ซึ่งเก็บ cache เป็น
`rep_<model>.<detector>.npz` ในโฟลเดอร์ `deepface_cache` ของฐานข้อมูล
ปัจจุบัน cache หลักเป็นไฟล์ `.sqlite3` ในโฟลเดอร์เดียวกัน และอัปเกรดจาก `.npz`
ให้อัตโนมัติครั้งเดียว — ไฟล์ `.npz` อื่นๆ (เช่น `ds_model_...npz`) เป็นของ
สคริปต์ `face.py` แยกส่วน ไม่ใช่ของแอป

### v1.1.2 — เปิดโปรแกรมเร็วขึ้น + ปุ่มหยุดทำงานถูกต้อง

v1.1.1 มี 2 เรื่องที่ผู้ใช้รู้สึก:

1. **เปิดช้า** — ตอนเปิดต้องโหลด TensorFlow (~5 วินาที) ก่อนหน้าต่างจะขึ้นมา
   ทั้งที่ GUI เองเร็วมาก
2. **กดปุ่ม "หยุด" แล้วเหมือนไม่หยุด/ค้าง** — แม้หยุดแล้วโปรแกรมยังไปรัน
   บันทึก cache ซ้ำ + วิเคราะห์รูปเป้าหมายต่ออีกชุด ทำให้ดูค้าง

## วิธีใช้งาน

1. เปิด `Deeface.exe`
2. กด **📁 โฟลเดอร์ฐานข้อมูล** แล้วชี้ไปที่โฟลเดอร์ที่เก็บรูปพนักงานทั้งหมด
3. กด **🖼 รูปเป้าหมาย** แล้วเลือกรูปของคนที่ยังไม่รู้รหัส
4. กด **🔍 ค้นหาใบหน้า**
5. อ่านรหัสพนักงานอันดับ 1 (ด้านบนสุด) — และดู 3 อันดับแรกเพื่อยืนยันด้วยตา
   - กด **คัดลอกรหัส** เพื่อยกยอดรหัสไปวาง (Ctrl+V) ได้ทันที

## คำแนะนำการใช้งาน

- **การติดตั้งบนเครื่องใหม่:** คัดลอก **ทั้งโฟลเดอร์** ที่มี `Deeface.exe`
  ไปด้วยกัน โดยเฉพาะโฟลเดอร์ `models\` (ไฟล์โมเดล AI) — ไม่ต้องติดตั้ง Python
  และไม่ต้องต่ออินเทอร์เน็ต ถ้าคัดลอกแค่ `Deeface.exe` โปรแกรมจะเตือนว่า
  ไม่พบโมเดลและถามก่อนดาวน์โหลด

  ```
  Deeface\
  ├── Deeface.exe                      ← ตัวโปรแกรม (~473 MB)
  ├── models\.deepface\weights\        ← ไฟล์โมเดล AI (~864 MB) *จำเป็น*
  └── settings.json                    ← ค่าเริ่มต้น (ไม่บังคับ)
  ```
- **สลับภาษา:** กดปุ่ม `ไทย` / `EN` มุมขวาบน เปลี่ยนได้ทันทีทั้งหน้าจอ
- **รันแรกจะช้า:** การรันครั้งแรกต่อโฟลเดอร์ฐานข้อมูลหนึ่ง ๆ
  ระบบต้องวิเคราะห์ใบหน้าทุกรูป (หลักหมื่นรูปอาจใช้เวลานานตั้งแต่หลายนาทีถึงชั่วโมง)
  ระหว่างรันจะมีแถบความคืบหน้าและตัวเลขวินาที — อย่าปิดหน้าต่าง
- **รันต่อ ๆ มาจะเร็วมาก:** เมื่อรันเสร็จครั้งแรกแล้ว โปรแกรมจะเก็บ
  "ข้อมูลใบหน้า" (cache) ไว้ในโฟลเดอร์ฐานข้อมูลชื่อ `deepface_cache`
  รันครั้งต่อไปจะใช้แค่ไม่กี่วินาที และจะวิเคราะห์เฉพาะรูปใหม่ที่เพิ่มเข้าเท่านั้น
  — ย้ายโฟลเดอร์/เปลี่ยนชื่อไฟล์/จัดโฟลเดอร์ใหม่ ก็ยังใช้ cache เดิมได้
- **ย้ายเครื่อง:** คัดลอกทั้งโฟลเดอร์ฐานข้อมูลรวม `deepface_cache` ไปด้วย
  หรือถ้าไม่ได้คัดลอก cache ไป แอปจะดึง embedding ที่เคยคำนวณไว้จาก
  shared cache ของเครื่องปลายทางให้ก่อน (ถ้ามี)
- **โมเดล / ตัวตรวจจับใบหน้า:**
  - `VGG-Face` (ค่าเริ่มต้น) — สมดุลระหว่างความเร็วและความแม่นยำ
  - `ArcFace` / `Facenet512` — แม่นยำกว่าสำหรับกรณีจับคู่ไม่ค่อยตรง
  - ตัวตรวจจับ `opencv` เร็ว, `retinaface` แม่นยำกว่ากับรูปที่เอียง/มืด
  - หากเปลี่ยนโมเดลหรือตัวตรวจจับ cache จะถูกสร้างใหม่ (รันแรกช้าอีกครั้ง)
- **รูปเป้าหมายที่มีใบหน้้ามากกว่า 1 ใบ** โปรแกรมจะจับคู่ทุกรูปหน้าในรูป
  และคืนอันดับที่ดีที่สุด
- **ไฟล์รูปภาพ:** รองรับ .jpg .jpeg .png .bmp .webp .tif .tiff

## ไฟล์/โฟลเดอร์ที่เกี่ยวข้อง

| ไฟล์ | คำอธิบาย |
| --- | --- |
| `Deeface.exe` | ตัวโปรแกรม |
| `models\` | **ไฟล์โมเดล AI ที่แนบมากับโปรแกรม** (`.deepface\weights`) — ต้องคัดลอกไปด้วยตอนติดตั้งเครื่องใหม่ |
| `Deeface.log` | บันทึกการทำงาน/ข้อผิดพลาด (สร้างอัตโนมัติ) — ส่งไฟล์นี้มาเมื่อแจ้งปัญหา |
| `settings.json` | จำการตั้งค่าโฟลเดอร์/โมเดล/ภาษา ครั้งล่าสุด (สร้างอัตโนมัติ) |
| `<โฟลเดอร์ฐานข้อมูล>/deepface_cache/` | cache ข้อมูลใบหน้า (`.sqlite3`) — **อย่าลบ** ถ้าต้องการให้รันต่อไปเร็ว; ลบได้ผ่านปุ่ม ♻ ในโปรแกรม |
| `%LOCALAPPDATA%\Deeface\cache\` | shared cache ของเครื่อง — ใช้ embedding ซ้ำข้ามโฟลเดอร์ฐานข้อมูล (ลบได้ ไม่กระทบ) |

## ถ้าโปรแกรมรายงาน "ไม่พบใบหน้า"

- ลองเปลี่ยน **ตัวตรวจจับ** เป็น `retinaface`
- ลองเปลี่ยน **โมเดล** เป็น `ArcFace`
- ตรวจสอบว่ารูปเป้าหมายชัดเจน มีใบหน้าหันหน้าตรง และไม่มืด/เบลอเกินไป

## ข้อมูลเชิงเทคนิค

- สร้างด้วย Python + DeepFace (TensorFlow) + customtkinter, เติมด้วย PyInstaller
- โมเดล weights **แนบมากับโปรแกรม** ในโฟลเดอร์ `models\.deepface\weights`
  (VGG-Face 553 MB, Facenet512 91 MB, ArcFace 131 MB, Facenet 88 MB + haarcascade
  รวม ~864 MB) โปรแกรมตั้ง `DEEPFACE_HOME` มาที่ `models` เองอัตโนมัติ
  ถ้าไม่มีโฟลเดอร์นี้ (รันจาก source) จะใช้ `%USERPROFILE%\.deepface\weights`
  และถ้าไฟล์ขาดจะดาวน์โหลดครั้งแรกให้ (ต้องต่ออินเทอร์เน็ต)
- ฟอนต์ Cinzel / Spectral / Noto Serif Thai แนบอยู่ใน exe และลงทะเบียน
  แบบ private (`AddFontResourceExW`) — เครื่องปลายทางไม่ต้องติดตั้งฟอนต์
- หน้าจอใช้ design system QuestUI: พื้นหลัง `#1A0F0A`, การ์ด `#2C1A10`,
  ขอบ `#5C3D2E`, ทอง `#CA8A04`, แดงเข้ม `#991B1B`, ตัวอักษร parchment `#F5E6D3`
